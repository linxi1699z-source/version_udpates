# 文档说明

## 名词解释

| 术语 / 缩略词 | 说明 |
|---|---|
| APP 版本 | 移动端 Android、iOS 或 HarmonyOS 客户端版本，格式为 `major.minor.patch`。 |
| 站点 | 配置生效的数据域。中国大陆为独立数据域；美区和英区共用同一份全球数据域。 |
| 数据分区 | 服务端实际存储与读取的配置域：`cn` 对应中国大陆，`global` 对应美区与英区。 |
| 固件版本 | 戒指固件版本，格式为 `xx.yyy.zzz`，用于约束 APP 版本适配的硬件版本。 |
| 固件灰度配置 | 对指定固件及用户范围设置一般/强制更新策略的配置。 |
| 功能灰度配置 | 选择已存在的功能灰度方案的开关配置；原“功能恢复配置”统一更名为“功能灰度配置”。 |
| APP 灰度 | APP 灰度开关。开启时不要求上架包/商店链接，以灰度机制控制分发。 |
| 需强制更新版本 | 强制更新场景中被要求升级的旧 APP 版本区间，可配置多个连续或不重叠区间。 |
| 生效状态 | 版本配置的可用状态：`未生效` 或 `已生效`。新增、复制、编辑保存及批量更新后的记录均为未生效，需通过一键生效变更。 |
| 幂等键 | 前端生成并随写操作提交的 `operation_id`；用于避免网络重试或重复点击导致重复写入。 |

# 需求背景

## 产品 / 数据现状调研

APP 持续更新迭代后，低版本客户端需要通过一般更新或强制更新策略进行治理。现有后台已具备“APP 版本管理”能力，能够分别配置 Android、iOS、HarmonyOS 的版本更新，但仍存在以下问题：

- 发布新版本采用长弹窗，字段较多、纵向内容过长，查看和编辑效率低。
- 中国大陆、美区、英区需要分别操作，其中美区和英区实际使用同一份配置，重复维护成本高。
- 固件版本逐条设置时样式出现嵌套，无法直观表达各固件版本独立配置。
- 缺少跨站点复制、批量更新固件适配范围与配置后二次生效能力，操作风险和人工成本较高。
- 更新描述需要覆盖 18 种语言，现有逐语言输入方式效率低，缺少可下载模板与可直接回填的上传能力。

本期为既有功能优化迭代，不新建独立的版本管理系统；保留现有列表、站点管理、发布、查看、编辑和删除基础能力，并扩展配置结构、校验、状态与批量操作。

## 用户调研

使用角色为运营人员、版本发布人员和具备审核权限的管理员。典型场景包括：发布新版本时配置适配固件与多语言描述；从一个站点复制到另一个站点；紧急调整一批历史 APP 版本的适配固件；在检查完成后统一使配置生效。正式访谈结论与角色权限矩阵待补充。

# 目标与关键指标（KPI）

- 目标：
  1. 将发布新版本从弹窗改为独立页面，降低长表单配置遗漏和误操作风险。
  2. 以中国大陆独立、美区/英区共享的站点模型减少重复配置，同时允许跨站点复制。
  3. 通过独立固件卡片、即时区间校验、批量更新和一键生效，使版本治理过程可检查、可追溯、可控生效。
  4. 通过 18 语种表格、Excel 模板上传与直接回填，提高更新描述维护效率。

- KPI：
  1. 发布页面必填校验拦截率与提交失败原因可统计，因字段遗漏造成的服务端提交失败率目标低于 1%；统计口径待补充。
  2. 美区/英区相同配置的重复维护次数目标降低 50% 以上；基线与统计周期待补充。
  3. 批量更新与一键生效的成功操作均应具备审计记录，配置状态一致性目标为 100%。
  4. 更新描述模板导入后 18 个语种回填完整率目标为 100%。

## 5.2 产品流程图

主流程：进入 APP版本管理列表 → 选择站点和筛选条件 → 发布 / 查看编辑 / 复制 / 批量更新固件版本 / 一键生效 → 客户端与服务端完成即时校验 → 写入配置和审计日志 → 列表按当前站点分区刷新。

发布流程：选择当前站点 → 进入发布新版本页面 → 填写平台、版本、独立固件卡片、功能灰度、APP 灰度、应用信息与描述 → 提交校验 → 创建未生效版本记录 → 返回当前站点列表。

强制更新分支：更新方式切换为强制更新 → 自动打开更新弹窗开关 → 必填需强制更新版本和 APP 版本更新描述 → 可选填写操作系统最低版本 → 提交后创建未生效记录。

批量更新异常流程：任一站点重复、版本区间不合法、记录不存在或并发版本已变更时，整体不写入，保留弹窗并展示对应错误；服务端返回可定位到中继器行的错误信息。

一键生效流程：选择站点与 APP 版本区间 → 提交 → 服务端仅将匹配的未生效记录置为已生效，已生效记录忽略 → 写入审计日志 → 关闭弹窗并刷新列表。

预警与人工处理：批量更新或生效发生部分失败、数据分区映射异常、上传文件解析异常时，服务端记录错误日志并返回可读错误；监控阈值和告警责任人待补充。

## 5.4 功能说明

### 5.4.1 APP版本管理列表

#### 页面说明

页面目标：在当前站点数据域中检索、查看和操作 APP 版本配置，并作为发布、查看编辑、复制、批量更新和一键生效的统一入口。

入口：左侧导航“运营中心 > APP版本管理”；点击左侧“APP版本管理”直接进入本页面。

使用角色：具备版本配置查看权限的运营人员、版本发布人员、管理员。

权限：`app_version:list`。发布、编辑、复制、批量更新与一键生效分别受独立权限控制；具体角色及权限编码待补充。

页面结构：顶部面包屑为 Home 图标 > 运营中心 > APP版本管理；不展示重复页面标题。右上角固定站点选择器。筛选栏左侧为筛选条件，右侧依次放置“发布新版本”“批量更新固件版本”“一键生效”“操作指南”。

#### 列表筛选字段

| 字段（中文） | 是否必填 | 类型 | 默认值 | 规则 / 交互说明 |
|---|---|---|---|---|
| site_code（站点） | 是 | enum | `cn`（中国大陆） | 放在页面右上角；选项为中国大陆、美区、英区。美区和英区映射 `global` 数据分区，切换二者不显示 toast。切换后重置页码为 1 并刷新列表。 |
| platform_filter（平台） | 否 | array<enum> | `[android,ios,harmony]` | 下拉多选，选项 Android、iOS、Harmony；默认三个均选中，输入框展示“Android,iOS,Harmony”。 |
| update_method_filter（更新方式） | 否 | enum | `all` | 下拉单选：所有更新方式、一般更新、强制更新。 |
| page_no（页码） | 否 | int | `1` | 分页组件控制；切换筛选条件或站点后回到第 1 页。 |
| page_size（每页条数） | 否 | int | `10` | 选项 10、20、50；每个数据分区至少提供 10 条示例数据。 |

#### 列表字段

| 字段（中文） | 是否必填 | 类型 | 默认值 | 规则 / 交互说明 |
|---|---|---|---|---|
| app_version（版本号） | 是 | string | 无 | 按创建时间倒序；最新有效版本可展示“最新”标签。 |
| platform（平台） | 是 | enum | 无 | 展示 Android、iOS、HarmonyOS；文案与平台选项保持一致，Android 不显示“安卓”；列标题不展示排序小箭头。 |
| description_preview（APP版本更新描述） | 是 | string | 无 | 中国大陆读取中文描述；美区/英区读取英文描述；上传描述后直接展示文件中对应语种内容。 |
| firmware_range_summary（固件适配范围） | 是 | array<object> | 无 | 按独立固件卡片聚合展示固件类型和起止范围；结束值为空时展示“起始版本起”。 |
| update_method（更新方式） | 是 | enum | `normal` | 展示“一般更新”或“强制更新”。 |
| force_app_version_ranges（需强制更新版本） | 条件必填 | array<object> | 无 | 强制更新时展示多个 APP 版本区间；一般更新展示“-”。 |
| effective_status（状态） | 是 | enum | 历史数据为 `effective` | 展示“已生效”或“未生效”。 |
| updated_by（操作人） | 是 | string | 系统记录 | 展示最近一次写操作人。 |
| updated_at（更新时间） | 是 | datetime | 系统记录 | 格式 `YYYY-MM-DD HH:mm:ss`。 |
| actions（操作） | 是 | array | 权限控制 | 展示“查看与编辑”“复制”；删除沿用既有能力，具体权限和删除规则待补充。 |

#### 列表交互

| 触发位置 | 触发动作 | 前置条件 | 系统处理 | 结果 / 提示 |
|---|---|---|---|---|
| 站点选择器 | 切换站点 | 有列表权限 | 依据站点映射 `cn` 或 `global` 分区，清空筛选结果缓存并查询第 1 页 | 美区/英区切换不提示 toast；列表展示对应共享数据。 |
| 平台 / 更新方式 | 选择或重置 | 无 | 以选中条件查询当前分区 | 查询结果、总数和分页同步更新。 |
| 发布新版本 | 点击 | `app_version:create` | 跳转发布新版本页面，携带当前 `site_code` | 打开独立页面，不使用弹窗。 |
| 查看与编辑 | 点击 | `app_version:edit` 或 `app_version:view` | 跳转查看与编辑页面，加载指定记录 | 平台和版本号只读。 |
| 复制 | 点击 | `app_version:copy` | 跳转复制版本页面，携带源记录与源站点 | 复制页预填可复制字段并按站点规则生成配置。 |
| 批量更新固件版本 | 点击 | `app_version:batch_update` | 打开批量更新固件版本弹窗 | 默认 1 行中国大陆配置。 |
| 一键生效 | 点击 | `app_version:activate` | 打开一键生效弹窗 | 默认 1 行中国大陆配置。 |
| 分页 | 点击页码、上一页、下一页或跳转 | 当前页合法 | 使用当前筛选条件加载对应页 | 支持页码、省略号、前往指定页；每页条数切换后回到第 1 页。 |

#### 异常、审计与刷新

- 无数据时展示空态，不展示虚构记录。
- 列表查询失败时展示“加载失败，请重试”；错误码映射待补充。
- 列表内容以当前会话存储保留：页面刷新后仍可见本会话内新建记录；关闭网页/会话后不再保证保留。生产环境持久化策略待补充。
- 所有成功写操作完成后刷新当前站点列表；写操作失败不刷新已有数据。
- 查询不写审计；查看、发布、编辑、复制、批量更新、生效、删除（如保留）均写入操作审计。

### 5.4.2 发布新版本、查看与编辑

#### 页面说明

页面目标：完成单个 APP 版本的创建、查看和编辑，并确保平台、固件适配、灰度、应用分发与多语言描述配置完整且合法。

入口：列表“发布新版本”进入创建态；列表“查看与编辑”进入查看编辑态。

使用角色：具备创建或编辑权限的版本发布人员、管理员。

权限：创建态需 `app_version:create`；查看编辑态需 `app_version:view` 和/或 `app_version:edit`。无编辑权限时所有字段只读，具体只读操作边界待补充。

面包屑：运营中心 > APP版本管理 > 发布新版本；查看编辑页最后一级为“查看与编辑”。删除旧弹窗中的“发布新版本”标题、“版本信息”二级标题及“快速编辑”按钮。

布局规则：字段标签不换行；内容区左侧标签列适度向右收缩/表单区域加宽，长字段标题使用单行展示。更新描述采用两列表格，文本框支持换行与随内容自动增高。

#### 通用表单字段

| 字段（中文） | 是否必填 | 类型 | 默认值 | 规则 / 交互说明 |
|---|---|---|---|---|
| platform（平台） | 是 | enum | 无 | 卡片单选：Android、iOS、HarmonyOS；卡片同时展示系统 icon 和文案。未选择提示“请选择平台”。查看编辑态不可修改。 |
| app_version（版本号） | 是 | string | 无 | 格式 `^[1-9]\\d{0,8}\\.\\d{0,9}\\.\\d{0,9}$`；首段不能以 0 开头。为空提示“请输入版本号”，格式错误提示“请输入正确的版本号”。查看编辑态不可修改。 |
| firmware_types（固件版本） | 是 | array<enum> | 无 | 多选：Gen1、Gen2、Gen2 Air、Gen3、行业版；至少选 1 个，未选提示“请选择固件版本”。每次新增勾选保留其他已选卡片的输入数据。 |
| function_gray_enabled（功能灰度配置） | 否 | boolean | `false` | 排列在固件版本之后、APP灰度开关之前；开启后显示配置名称。 |
| function_gray_config_id（配置名称） | 条件必填 | string | 无 | 仅功能灰度配置开启时展示；下拉显示可选灰度功能方案（可使用示例项“睡眠算法灰度A”“健康报告灰度B”“会员权益灰度C”）；未选择提示“请选择功能灰度配置”。 |
| app_gray_enabled（APP灰度开关） | 否 | boolean | `false` | 排列在功能灰度配置之后。开启后 Android 隐藏 APK 文件字段，iOS/HarmonyOS 隐藏 URL 字段，并取消相应必填校验。 |
| update_method（更新方式） | 是 | enum | `normal` | 单选“一般更新”“强制更新”；创建态默认一般更新且展示字段，查看编辑态可修改。切换强制更新时自动打开 `update_dialog_enabled`。 |
| update_dialog_enabled（更新弹窗） | 否 | boolean | `false` | 强制更新时自动设为开启；一般更新不强制开启，允许按既有权限手动控制。 |

#### 独立固件配置卡片字段

每个被选中的 `firmware_type` 渲染一张平级、互不嵌套的独立卡片；卡片标题显示“固件版本配置”和固件标签。选中 Gen1、Gen2、Gen2 Air、Gen3、行业版中的任意多项时，分别生成对应卡片，不能在 Gen1 卡片内部嵌套 Gen2 等卡片。

| 字段（中文） | 是否必填 | 类型 | 默认值 | 规则 / 交互说明 |
|---|---|---|---|---|
| firmware_type（固件版本） | 是 | enum | 对应已选项 | 纯文本，不可编辑；与卡片绑定。 |
| adapted_firmware_start（适配固件开始版本） | 是 | string | 无 | 从已有固件版本中选择；格式 `xx.yyy.zzz`；未填提示“请输入固件版本”。 |
| adapted_firmware_end（适配固件结束版本） | 否 | string | 无 | 从已有固件版本中选择，可为空。开始和结束同时有值时必须开始小于等于结束；选择任一值后立即校验，错误提示“开始版本需要小于等于结束版本”。 |
| firmware_gray_enabled（固件灰度配置） | 否 | boolean | `false` | 开启后展示灰度版本、特殊 IDs、尾号数、范围和灰度更新方式。 |
| special_ids（特殊 IDs） | 否 | string | 无 | 仅固件灰度开启时展示；格式、长度和分隔符规则待补充。 |
| tail_number（尾号数） | 否 | string | 无 | 仅固件灰度开启时展示；格式规则待补充。 |

#### 状态流转

| 当前状态 | 触发动作 | 前置条件 | 目标状态 | 说明 |
|---|---|---|---|---|
| 不存在 | 发布新版本 | 全部校验通过 | 未生效 | 新建版本默认不直接生效。 |
| 已生效 / 未生效 | 查看与编辑后保存 | 全部校验通过 | 未生效 | 任意编辑保存均需要重新一键生效。 |
| 不存在 | 复制版本提交 | 目标站点均校验通过 | 未生效 | 对每个目标数据分区创建记录。 |
| 已生效 / 未生效 | 批量更新固件版本 | 全部站点事务提交成功 | 未生效 | 固件适配范围被改动后需重新生效。 |
| 未生效 | 一键生效提交 | 记录匹配且版本范围合法 | 已生效 | 可被客户端读取为有效配置。 |
| 已生效 | 一键生效提交 | 记录匹配 | 已生效 | 幂等忽略，不再次处理。 |

#### 重复拦截

| 场景 | 判重字段 | 拦截规则 | 提示文案 |
|---|---|---|---|
| 发布 / 复制版本 | data_partition + platform + app_version | 有效记录中不允许创建同一分区、平台、版本号的重复配置 | 该站点已存在相同平台和版本号配置。 |
| 批量更新固件版本 | items.data_partition | 同一次请求中不允许重复站点；美区和英区视为同一全球分区 | 站点重复。 |
| 一键生效 | items.data_partition | 同一次请求中不允许重复站点；美区和英区视为同一全球分区 | 站点重复。 |
| 固件配置 | firmware_type | 同一版本记录中每个固件类型仅保留一张独立卡片 | 当前固件版本已配置。 |
| 强制更新版本区间 | 相邻区间的版本边界 | 下一区间开始版本不得小于上一区间结束版本 | 开始版本需要小于等于结束版本。 |

#### 幂等规则

| 场景 | 幂等键 | 处理规则 |
|---|---|---|
| 发布新版本 | operation_id + data_partition + platform + app_version | 首次成功创建后缓存结果；相同幂等键重试返回首次记录，不重复创建。 |
| 编辑保存 | operation_id + app_version_id | 同一幂等键只应用一次字段变更与状态重置。 |
| 复制版本 | operation_id + source_app_version_id + target_partitions | 对同一目标分区最多创建一次；全部成功才返回成功。 |
| 批量更新固件版本 | operation_id | 服务端记录每个站点行的处理结果；重试直接返回首次完整结果，不重复标记未生效。 |
| 一键生效 | operation_id | 对已生效记录天然幂等；重试返回首次命中/跳过统计。 |
| 上传描述 | file_hash + app_version_draft_id | 相同文件重复上传不重复生成描述行，仅覆盖同一草稿的对应语种。 |

#### 接口 / 服务端逻辑

| 模块 | 说明 |
|---|---|
| 查询服务 | 1. 接收 `site_code` 并映射 `data_partition`；2. 应用平台、更新方式、分页筛选；3. 美区和英区返回同一全球分区数据；4. 返回列表、总数、分页和展示用描述。接口路径待补充。 |
| 发布 / 编辑服务 | 1. 校验权限、幂等键、版本格式、固件区间、灰度范围、灰度版本边界、描述完整性与站点默认值；2. 事务写入主记录、固件子项、描述子项与审计；3. 创建或保存后状态设为 `pending_effective`；4. 返回记录 ID 与状态。 |
| 上传描述服务 | 1. 校验扩展名 `.xlsx`、文件大小不超过 5M、模板仅含语种与更新描述两列；2. 校验 18 个语种覆盖及无重复；3. 解析成功后返回 `localized_descriptions`，由前端直接回填；4. 不返回需展示的文件名。解析失败不覆盖现有草稿。 |
| 复制服务 | 1. 校验源记录可读、目标站点合法和分区去重；2. 按 `cn`/`global` 生成站点卡，处理默认 URL/AndroidAppId 与清空 APK/协议版本；3. 事务创建目标记录；4. 全部目标分区成功后返回。 |
| 批量更新服务 | 1. 按分区去重并校验各区间；2. 事务锁定命中 APP 版本；3. 更新固件适配范围并置未生效；4. 任一行失败整体回滚；5. 返回成功/失败行、变更数量和审计 ID。 |
| 一键生效服务 | 1. 按分区去重和 APP 版本范围查询；2. 仅更新 `pending_effective`；3. 已生效记录计入跳过数；4. 写审计；5. 返回 `updated_count`、`skipped_count`。 |
| 字典依赖 | 平台、固件版本、协议版本、功能灰度配置名称、可选 APP版本均读取已有字典或服务；具体接口、缓存和失效策略待补充。 |

接口异常与重试：客户端可对网络超时进行有限次数重试，重试必须携带原 `operation_id`；服务端业务校验失败不重试；事务和数据库异常返回可追踪错误 ID 并触发监控。重试次数、超时值、错误码与告警阈值待补充。

# 非功能需求

## 财务需求

本期不涉及支付、金额、账务或结算逻辑。

## 运营或产品

- 权限应按列表查看、创建、编辑、复制、批量更新、生效、删除（如保留）分离；角色和授权链路待补充。
- 所有写操作应留存前后快照、站点、数据分区、操作人、操作时间、结果、失败原因与幂等键，支持按记录 ID 检索；审计保留时长待补充。
- 中国大陆与全球分区的数据隔离必须明确；美区/英区切换只影响展示站点，不创建两份全球配置。
- 发布、复制、批量更新和编辑后的记录必须为未生效，只有一键生效可转为已生效。

## UI

- 保持既有后台的浅色、表格化管理界面风格，发布表单由弹窗改为页面。
- 面包屑使用 Home 图标 > 运营中心 > APP版本管理；发布、查看编辑、复制页面增加对应末级面包屑。
- 平台选项展示系统 icon 与文案；列表平台不展示排序箭头。
- 表单标签不得换行；重复器和固件卡片均以平级块展示，避免嵌套关系误解。
- 更新描述两列表格支持多行输入和自动增高；上传区域不展示上传文件名及冗余自动生成说明。
- 分页默认每页 10 条，支持 10/20/50、页码、省略号、前后翻页和跳页。

## 研发

- 前端与服务端必须同时实现版本区间、固件区间、灰度范围与多区间顺序校验；前端用于即时反馈，服务端为最终拦截。
- 所有写接口采用 `operation_id` 幂等；批量更新与复制的多分区操作采用事务或等效补偿机制，禁止部分成功后仍返回成功。
- 文件上传仅允许 XLSX 且不超过 5M；服务端应校验 MIME、后缀、列头、语种覆盖和潜在公式/恶意文件风险。存储服务、病毒扫描与保留策略待补充。
- 关键查询、提交、批量事务应具备可观测性；性能指标、并发量、SLA、数据库索引方案、缓存策略与容量规划待补充。
- Web 端会话刷新保留草稿/示例数据属于原型行为；生产持久化、登录会话和数据清理策略需在技术方案中确认。

1. 页面文案是否需要多语言：本期后台页面文案沿用既有管理后台语言策略，具体语言包范围待补充；APP 版本更新描述必须支持多语言。
