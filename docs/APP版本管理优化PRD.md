# APP 版本管理优化 PRD

| 项目 | 内容 |
| --- | --- |
| 产品名称 | APP 版本管理优化 |
| 文档版本 | V1.0 |
| 需求类型 | 现有后台功能优化迭代 |
| 适用端 | 运营管理后台 Web |
| 涉及平台 | Android、iOS、HarmonyOS |

## 1. 背景与目标

APP 持续迭代后版本数量增多，运营人员需要按中国大陆、美区、英区配置版本更新、固件适配和灰度策略。现有功能以发布弹窗和单条维护为主，站点间配置重复，且缺少复制、批量调整与配置生效控制能力。

本需求在已有“APP 版本管理”后台能力上优化，不新建独立系统。目标如下：

1. 将发布流程由长弹窗调整为独立页面，提升复杂配置的可读性与可维护性。
2. 完善版本、固件、灰度、更新描述和强制更新的字段与即时校验。
3. 通过复制、批量更新固件版本降低跨站点和多版本维护成本。
4. 将“配置保存”和“配置生效”解耦：新增、编辑、复制及批量更新后均为未生效，需通过一键生效批量确认后下发。

## 2. 范围与术语

### 2.1 站点与数据分区

| 站点 | 说明 | 数据规则 |
| --- | --- | --- |
| 中国大陆 | 中国大陆运营站点 | 独立配置与数据 |
| 美区 | 美国运营站点 | 与英区共用一份配置与列表数据 |
| 英区 | 英国运营站点 | 与美区共用一份配置与列表数据 |

- 列表页默认站点为“中国大陆”。
- 切换美区或英区时展示同一套数据；站点切换不弹出 Toast。
- 原型数据刷新页面后仍可见；关闭浏览器标签页/网页会话后不再保留。正式实现可使用会话级缓存或等价机制满足该体验。

### 2.2 关键术语

| 术语 | 定义 |
| --- | --- |
| APP 灰度 | APP 发布灰度。开启后不再要求 Android 上传 APK，iOS/HarmonyOS 不再要求填写 URL。 |
| 固件灰度配置 | 在某固件适配卡片内，针对特殊用户或范围下发指定固件与更新方式的策略。 |
| 功能灰度配置 | 既有“功能恢复配置”改名，用于选择已有的功能灰度配置名称。 |
| 需强制更新版本 | 强制更新时指定需被强制更新的旧 APP 版本区间，可配置多段。 |
| 已生效/未生效 | 配置是否已通过“一键生效”确认下发的状态。 |

## 3. 信息架构与通用交互

### 3.1 页面入口与面包屑

- 左侧导航点击“APP版本管理”，进入 APP 版本管理列表页。
- 列表页面包屑：`Home 图标 > 运营中心 > APP版本管理`。
- 发布页面包屑：`运营中心 > APP版本管理 > 发布新版本`。
- 查看与编辑页面包屑：`运营中心 > APP版本管理 > 查看与编辑版本`。
- 复制页面包屑：`运营中心 > APP版本管理 > 复制版本`。
- 列表页不展示重复的“APP版本管理”页面标题；发布页不展示“发布新版本”大标题和“版本信息”二级标题。

### 3.2 页面样式原则

- 沿用现有后台的白底卡片、浅灰表头、主色蓝按钮、次级描边按钮及紧凑表格样式。
- 站点选择器位于列表页面右上角。
- 复杂字段使用“标签列 + 内容列”布局；字段标签不得换行。必要时增加左侧标签列宽或整体表单宽度，避免标签被折行。
- 平台卡片、固件选项和状态标签需具有清晰的选中、禁用、已生效和未生效视觉状态。

## 4. APP 版本管理列表页

### 4.1 顶部筛选与操作区

筛选栏左侧为筛选条件，右侧按以下顺序放置操作按钮：

1. 发布新版本（主按钮）
2. 批量更新固件版本
3. 一键生效
4. 操作指南

| 条件 | 控件 | 规则 |
| --- | --- | --- |
| 平台 | 下拉多选 | Android、iOS、Harmony；默认全选，收起时展示 `Android,iOS,Harmony`。 |
| 更新方式 | 下拉单选 | 所有更新方式（默认）、一般更新、强制更新。 |
| 重置 | 按钮 | 恢复默认筛选条件并回到第 1 页。 |

### 4.2 列表字段

列表按当前站点数据和筛选条件展示，列顺序如下：

| 列 | 展示规则 |
| --- | --- |
| 版本号 | APP 版本号；最新版本可展示“最新”标签。 |
| 平台 | 固定显示 `Android`、`iOS`、`Harmony`，不显示排序箭头；Android 不得显示为“安卓”。 |
| APP 版本更新描述 | 中国大陆展示中文描述；美区/英区展示英文描述。上传描述文件后的内容直接用于该列展示。 |
| 固件适配范围 | 展示各已配置固件类型及其适配区间。批量更新后展示批量设置的固件区间。 |
| 更新方式 | 一般更新或强制更新。 |
| 需强制更新版本 | 强制更新时展示所有区间，以 `开始版本—结束版本` 表示，多段以分号分隔；一般更新展示 `—`。 |
| 状态 | 已生效或未生效。存量数据默认已生效。 |
| 操作人 | 最后配置人。 |
| 更新时间 | 最后配置时间。 |
| 详情 | 查看与编辑、复制、删除（删除沿用现有能力/策略）。 |

### 4.3 分页

- 默认每页 10 条，可选择 10、20、50 条/页。
- 显示上一页、下一页、页码、超过页码数时的省略号，以及页码跳转输入框。
- 当前页使用主色蓝；不可用的前后翻页使用禁用样式。
- 切换站点、变更筛选条件或重置筛选条件时重新计算分页并回到第 1 页。
- 中国大陆数据与美区/英区共享数据分区均应至少提供 10 条样例记录，用于验证分页及筛选。

## 5. 发布新版本

### 5.1 页面与提交结果

- 点击“发布新版本”进入独立发布页，不再使用弹窗。
- 提交成功后在当前站点创建版本记录，记录状态为“未生效”，需后续通过一键生效处理。
- 发布页展示更新方式字段，默认“一般更新”。

### 5.2 字段顺序与配置

| 顺序 | 字段 | 控件与规则 |
| --- | --- | --- |
| 1 | 平台 | 必填，Android、iOS、HarmonyOS 单选卡片；每张卡片需同时展示系统 Icon 和文案。 |
| 2 | 版本号 | 必填输入框，格式为 `{1,9}.{0,9}.{0,9}`，首段不得以 0 开头，例如 `4.3.0`。 |
| 3 | 固件版本 | 必填多选：Gen1、Gen2、Gen2 Air、Gen3、行业版。 |
| 4 | 各固件版本配置 | 每个已勾选固件版本独立展示一张配置卡，互不嵌套。新增勾选项不得清空已勾选固件的输入值。 |
| 5 | 功能灰度配置 | 开关，默认关闭；开启后显示配置名称下拉框，选择已有的功能灰度配置。 |
| 6 | APP 灰度开关 | 开关，默认关闭。 |
| 7 | 应用包/商店信息 | 根据平台和 APP 灰度开关显示 APK、URL、AndroidAppId、协议版本。 |
| 8 | 更新方式 | 一般更新/强制更新单选，默认一般更新。 |
| 9 | 强制更新扩展配置 | 仅强制更新时展示需强制更新版本、操作系统最低版本和更新弹窗。 |
| 10 | APP 版本更新描述 | 18 种语言描述录入与 Excel 上传。 |

### 5.3 固件版本配置卡

每个已选固件版本显示以下独立字段：

| 字段 | 规则 |
| --- | --- |
| 固件版本 | 纯文本，等于勾选的固件类型，不可编辑。 |
| 适配固件 | 必填区间下拉框，最低固件版本必选，最高固件版本可空。固件格式为 `xx.yyy.zzz`。 |
| 固件灰度配置 | 开关，默认关闭；开启后展示灰度策略字段。 |
| 特殊 IDs / 尾号数 | 固件灰度策略中的文本输入项，按既有数据规则保存。 |
| 范围 | 至少保留一行范围；输入项仅允许整数。第一行提示“起始范围如 1”“结束范围如 9999”。点击“增加范围”新增区间；范围行数大于 1 时显示“删除范围”，仅删除对应行。 |
| 固件灰度版本 | 固件版本下拉框。开启固件灰度时必选，且必须位于适配固件区间内。 |
| 灰度更新方式 | 一般更新/强制更新单选。 |

#### 5.3.1 固件版本比较规则

- `xx.yyy.zzz` 三段均按数值比较，比较前各段可去除前导 0。
- 例如 `01.001.003 < 01.001.007`；先比较 xx，相同再比较 yyy，仍相同再比较 zzz。
- 适配固件已同时选择开始、结束值时，开始值必须小于等于结束值；结束值可空。
- 灰度范围已同时填写起始、结束值时，起始值必须小于等于结束值。
- 用户选择造成区间不合法时，应立即提示“开始版本需要小于等于结束版本”或“起始范围需要小于等于结束范围”，不能仅在提交时提示。

### 5.4 功能灰度与 APP 灰度

| 字段 | 规则 |
| --- | --- |
| 功能灰度配置 | 默认关闭；开启后配置名称必选，未选提示“请选择功能灰度配置”。可提供若干既有灰度配置样例作为下拉选项。 |
| APP 灰度开关 | 默认关闭。开启后 Android 隐藏 APK 文件字段且不校验 APK；iOS/HarmonyOS 隐藏 URL 字段且不校验 URL。 |

### 5.5 应用包、URL、应用 ID 与协议版本

| 平台 | 字段 | 默认值与规则 |
| --- | --- | --- |
| Android | APK 文件 | APP 灰度关闭时必填，上传控件文案“点击上传”。 |
| Android | AndroidAppId | 必填；中国大陆默认 `com.szjztech.ringconn`，美区/英区默认 `com.gdjztech.ringconn`。 |
| iOS | URL | APP 灰度关闭时必填；中国大陆默认 `https://itunes.apple.com/cn/app/id6479988118`，美区/英区默认 `https://itunes.apple.com/cn/app/id6444470583`。 |
| HarmonyOS | URL | APP 灰度关闭时必填；所有站点默认 `https://appgallery.huawei.com/app/detail?id=com.szjztech.ringconn.hm`。 |
| 全平台 | 协议版本 | 必填下拉框，展示既有协议版本号，例如 `4.4.0`、`2.2.0`。 |

### 5.6 强制更新

- 更新方式选择“强制更新”后，更新弹窗自动开启，并且 APP 版本更新描述为必填。
- 选择“一般更新”时，不强制开启更新弹窗；运营人员可按既有能力自行设置。
- 强制更新时展示“需强制更新版本”和“操作系统最低版本”。

#### 5.6.1 需强制更新版本

- 为 APP 版本区间中继器，仅可从当前站点已有 APP 版本中选择。
- 每个区间开始版本必选，结束版本可不选；同一区间开始版本必须小于等于结束版本。
- 点击“新增”增加一段区间；新增后即可展示对应“删除区间”操作，至少保留一段。
- 多段区间按页面顺序校验：下一段开始版本必须大于等于上一段结束版本。若上一段存在下一段，则上一段结束版本必须填写。
- 用户每次选择开始或结束版本时立即校验，错误提示为“开始版本需要小于等于结束版本”或相应相邻区间提示。

#### 5.6.2 操作系统最低版本

- 非必填，仅在强制更新时展示。
- Android 最低版本输入框带 `Android` 前缀，提示语“如 16”，仅允许输入非 0 正整数。
- iOS 最低版本输入框带 `iOS` 前缀，格式为 `xx.yy.zz`；三段均为数字，首段不得以 0 开头，例如 `16.00.00`。

### 5.7 APP 版本更新描述与上传模板

- 字段名称统一为“APP 版本更新描述”。
- 按固定顺序用两列表格展示：第一列“语种”，第二列“APP 版本更新描述”。
- 语种顺序：中文、英语、繁体中文、德语、法语、日语、西班牙语、阿拉伯语、捷克语、波兰语、土耳其语、芬兰语、意大利语、匈牙利语、罗马尼亚语、韩语、立陶宛语、马来语。
- 文本框支持换行，内容换行后高度自动增长。
- 提供“上传描述”按钮，仅支持 `.xlsx`，文件不大于 5 MB；按钮右侧依次显示“文件大小 ≤ 5M”“下载模板”。
- 下载模板为 `.xlsx`，仅两列：语种、更新描述；预置全部 18 种语言。
- 上传成功后直接回填各语言文本，不 Toast 成功提示，不回显文件名，也不展示“已自动生成 18 种语言的更新描述”等说明。可显示简短状态“已上传翻译”。
- 列表应直接显示上传文件中与当前站点对应语言的描述。
- 查看与编辑、复制页应自动带出完整的必填字段；如无上传翻译文件，可用预置的 AI 生成内容补全 18 种语言描述，供运营人员编辑。

### 5.8 发布校验与提示

| 校验对象 | 触发条件 | 提示语 |
| --- | --- | --- |
| 平台 | 未选择 | 请选择平台 |
| 版本号 | 未填写 | 请输入版本号 |
| 版本号 | 格式错误 | 请输入正确的版本号 |
| 固件版本 | 未勾选任何项 | 请选择固件版本 |
| 适配固件 | 开始版本未选 | 请输入固件版本 |
| 适配固件 | 区间不合法 | 开始版本需要小于等于结束版本 |
| 固件灰度版本 | 灰度开启但未选 | 请选择固件灰度版本 |
| 固件灰度版本 | 不在适配区间 | 固件灰度版本需在适配固件区间内 |
| 固件灰度范围 | 非整数 | 灰度范围只能输入整数 |
| 功能灰度配置 | 开启但未选配置 | 请选择功能灰度配置 |
| APK | Android 且 APP 灰度关闭、未上传 | 请上传 APK 文件 |
| URL | iOS/HarmonyOS 且 APP 灰度关闭、未填写 | 请输入 URL |
| AndroidAppId | Android 未填写 | 请输入Android APP ID |
| 协议版本 | 未选择 | 请选择协议版本 |
| APP 版本更新描述 | 任一语言为空 | 请填写所有语种对应描述 |

## 6. 查看与编辑页面调整

- 查看与编辑页面复用发布新版本的页面结构、字段顺序、默认值规则和校验规则。
- 平台与版本号不可编辑，其余允许修改。
- 修改并保存后，记录状态变更为“未生效”，即使该记录此前已生效。
- 更新方式可在此页面修改；切换为强制更新时展示并校验强制更新扩展字段。
- 页面不展示“快速编辑”按钮。
- 查看已有样例数据时，应自动回填对应固件配置、灰度策略、应用信息、协议版本、更新描述、强制更新版本和系统最低版本等必填数据。

## 7. 复制版本

### 7.1 入口与基本规则

- 列表“详情”列新增/保留“复制”操作。
- 点击后进入“复制版本”页面，主体字段与发布新版本页面一致，源记录的公共配置全部带出且允许修改。
- 复制提交生成新记录，状态为“未生效”。

### 7.2 站点中继器

- 在 APP 灰度开关之后新增“站点”多选字段，选项为中国大陆、美区、英区。
- 被复制记录的源站点不可再次作为目标站点；目标站点仅展示可复制的其他站点。
- 选择站点后，根据数据分区展示对应的站点配置卡。美区和英区使用同一份配置，只需填写一张“美区/英区”配置卡；若同时选择中国大陆，则额外展示一张中国大陆配置卡。
- 站点配置卡包含 APK 文件、URL、AndroidAppId、协议版本；这些字段随站点独立保存。

### 7.3 复制默认值与预填规则

| 源记录站点 | 目标站点默认勾选与配置 |
| --- | --- |
| 中国大陆 | 可选美区、英区；两者共用一份美区/英区配置。除默认 URL/AndroidAppId 外，APK 和协议版本为空，需要手动设置。 |
| 美区 | 英区为可见且默认勾选的目标站点，其配置与美区源数据一致；中国大陆可选，除默认 URL/AndroidAppId 外，APK、协议版本为空。 |
| 英区 | 美区为可见且默认勾选的目标站点，其配置与英区源数据一致；中国大陆可选，除默认 URL/AndroidAppId 外，APK、协议版本为空。 |

- iOS URL、HarmonyOS URL、AndroidAppId 的站点默认值遵循第 5.5 节。
- 当源记录属于美区/英区时，其共享分区的 APK、URL、AndroidAppId、协议版本应完整带入到对方站点配置中。
- 复制校验按每个目标数据分区独立执行；APP 灰度关闭时，Android 需上传 APK，iOS/HarmonyOS 需填写 URL；AndroidAppId 与协议版本仍为必填。

## 8. 批量更新固件版本

### 8.1 入口与弹窗

- 列表操作区提供“批量更新固件版本”按钮。
- 点击后打开居中弹窗，标题“批量更新固件版本”加粗。
- 弹窗内使用站点配置中继器；默认一条中国大陆配置，可新增站点配置。配置数量大于等于 2 时展示删除操作，至少保留一条。

### 8.2 每条站点配置

| 字段 | 规则 |
| --- | --- |
| 站点 | 下拉：中国大陆、美区、英区；默认中国大陆。相同站点不得重复。 |
| APP 版本 | APP 版本区间，开始版本必选、结束版本可空；从对应站点现有 APP 版本中选择；开始版本小于等于结束版本。 |
| 固件版本 | 固件版本区间，开始版本必选、结束版本可空；从已有固件版本中选择；开始版本小于等于结束版本。 |

- 站点重复时立即提示“站点重复”。
- 已填写另一端值时，用户再次选择导致区间逆序的值，应立即提示“开始版本需要小于等于结束版本”。

### 8.3 提交与状态

- 提交时，仅在全部站点配置校验通过后统一更新对应站点、对应 APP 版本区间内的固件适配范围。
- 操作成功后，所有受影响 APP 版本记录状态均置为“未生效”，关闭弹窗并提示“各个站点数据已更新”。
- 取消或关闭直接隐藏弹窗，不保存任何变更。

## 9. 一键生效

### 9.1 目的与入口

为避免配置保存后直接下发，新增“一键生效”作为显式的二次确认批量操作。按钮位于“批量更新固件版本”之后。

### 9.2 生效弹窗

- 点击“一键生效”后展示标题为“一键生效”的弹窗。
- 使用站点配置中继器；默认一条中国大陆配置，支持新增、删除，至少保留一条。
- 每条配置包括：

| 字段 | 规则 |
| --- | --- |
| 生效站点 | 下拉：中国大陆、美区、英区；同一弹窗内不得重复。 |
| APP 版本 | APP 版本区间。开始版本必选、结束版本可空，仅可选择对应站点已有 APP 版本；开始版本小于等于结束版本。 |

- 重复选择站点时立即提示“站点重复”。
- 区间逆序时立即提示“开始版本需要小于等于结束版本”。

### 9.3 提交与状态流转

- 点击“提交”后，匹配站点及 APP 版本区间内所有“未生效”记录状态更新为“已生效”。
- 已经是“已生效”的记录忽略，不重复处理，也不报错。
- 提交完成后关闭弹窗；取消/关闭则不保存。
- 推荐成功提示：“站点 APP 版本已生效”。

## 10. 状态流转

| 操作 | 结果状态 |
| --- | --- |
| 既有存量记录 | 已生效 |
| 发布新版本成功 | 未生效 |
| 查看与编辑保存成功 | 未生效 |
| 复制并发布成功 | 未生效 |
| 批量更新固件版本成功 | 被影响记录变为未生效 |
| 一键生效提交成功 | 命中且未生效的记录变为已生效 |

## 11. 验收标准

1. APP 版本管理为现有后台入口下的优化页面，非新增独立系统。
2. 列表默认展示中国大陆数据；美区与英区数据完全共享。
3. 筛选、分页、站点切换均可用，默认每页 10 条。
4. 列表平台列无排序箭头，Android 文案正确，新增状态列与需强制更新版本列展示正确。
5. 发布新版本由弹窗改为独立页面，面包屑、按钮位置和标题展示符合本 PRD。
6. 平台卡片有图标与文案；查看与编辑时平台、版本号不可编辑。
7. Gen1、Gen2、Gen2 Air、Gen3、行业版均可选，且每个固件配置卡相互独立、输入值可保留。
8. 固件区间、灰度区间、APP 版本区间均具备即时校验与提交校验。
9. APP 灰度、功能灰度、固件灰度的开关显隐、必填校验及默认值符合本 PRD。
10. 各站点 URL、AndroidAppId 默认值准确；HarmonyOS URL 不受站点影响。
11. 强制更新自动开启更新弹窗，支持多段需强制更新版本和系统最低版本格式校验。
12. 18 种语言按固定顺序展示，模板可下载、上传后直接回填且列表展示相应语言描述。
13. 复制功能能按站点数据分区预填和保存，不会覆盖源站点记录。
14. 批量更新固件版本支持多站点中继器、重复站点提示及成功后置未生效。
15. 一键生效支持多站点中继器、重复站点提示、版本区间校验，并仅生效未生效记录。
16. 刷新页面后本会话新增/修改记录仍可见；关闭会话后不要求保留。
